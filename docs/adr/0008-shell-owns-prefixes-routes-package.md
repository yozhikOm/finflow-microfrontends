# Shell знает только префиксы, публичные адреса — в пакете `routes`

`shell` держит один роутер React Router в Data Mode и по маршруту на каждое remote-приложение: `accounts/*`, `transactions/*`, `analytics/*`. Remote-приложение отдаёт через Module Federation компонент `./App` со своими вложенными `<Routes>` и внутри префикса распоряжается путями само: новая страница в `accounts` не требует выката `shell`. Адреса, на которые ссылаются соседи, и сами префиксы — контракт владельца: они объявлены в npm-пакете `@yozhikom/finflow-routes`, который, как `events` (ADR-0006), каждое приложение бандлит своей версией вне `shared`. Полная таблица путей в `shell` связала бы его выкат с каждой страницей remote-приложений, а `patchRoutesOnNavigation` в связке с Module Federation описан одной строкой документации, и что делать при сбое загрузки внутри него, не сказано.

## Consequences

- Вложенные `<Routes>` не получают `loader`, `action` и `lazy` React Router. Это не потеря: данные загружает Apollo (ADR-0006).
- Каркас страницы и навигацию рисует `shell`, названия разделов — его, префиксы — из пакета `routes`. `/` перенаправляет на `/transactions`. Неизвестный префикс — 404 `shell`, неизвестный путь внутри префикса — 404 remote-приложения.
- Публичные адреса MVP: `/transactions` с необязательными комбинируемыми фильтрами `category`, `month` (`YYYY-MM`), `currency`, `account` в query; `/transactions/new` с необязательным `account`; `/accounts/<id>`; `/analytics`. Внутренние пути (`categories`, `<id>/edit`, месяц и валюта `analytics`) в пакет не входят, ссылки на них относительные.
- Для каждого публичного адреса пакет даёт пару функций: построить адрес и разобрать его в типизированные параметры. Разбор молча отбрасывает параметры неверной формы (`month=2026-13`). Существование сущности проверяет владелец: несуществующий id в фильтре даёт пустой список с видимым сбрасываемым фильтром, архивный счёт в `/transactions/new?account=` не предвыбирается.
- Ссылки на соседей и на собственные публичные адреса строятся только через пакет. Новый адрес или параметр — minor, переименование или удаление, включая смену префикса, — major.
- Если `./App` раздела не загрузился, шапка и остальные разделы работают, а маршрутный `ErrorBoundary` в `shell` показывает «Раздел «…» временно недоступен» с кнопкой «Повторить». Кнопка повторяет загрузку без перезагрузки страницы, а если повтор remote-модуля так не срабатывает, перезагружает страницу. Повторы запросов и `errorLoadRemote` сюда не входят.
- Remote-приложение для отдельного запуска монтирует свой `./App` на тот же префикс в своём роутере.

## Considered Options

- Хост владеет всеми путями, remote-приложения отдают страницы: ссылки самые простые, но каждая новая страница требует выката `shell`.
- Remote-приложение отдаёт описания маршрутов, `shell` подгружает их через `patchRoutesOnNavigation`: сохраняет data API, но обработка сбоя загрузки не описана и не проверена.
- Построители адресов в пакете `events`, переименованном в общий пакет контрактов: пересматривает ADR-0006 ради экономии одного пакета.
- Построители адресов как экспорт Module Federation: ссылка на соседа ломается, когда его код не загрузился, хотя переход мог бы сработать.
- Адреса строками по документации: разойдутся, как разошлись ручные типы транзакций (ADR-0002).
