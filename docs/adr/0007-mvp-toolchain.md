# React Router v8 общим синглтоном без Bridge Router, тулчейн одной мажорной версии

Все приложения FinFlow маршрутизируют через React Router v8, а `react-router` входит в `shared` как синглтон. Module Federation React Bridge Router, который даёт каждому remote-приложению свой роутер, не используется. Bridge в `@module-federation/bridge-react@2.9.3` официально поддерживает React Router только `^6 || ^7`: на v8 он молча подставляет алиасы v7, а алиаса на `react-router/dom` у него нет. Кроме того, синхронизация в Bridge односторонняя (хост → remote), и штатно сослаться из remote-приложения на страницу другого нельзя, а MVP такие ссылки нужны («счёт → его транзакции», «категория в аналитике → отфильтрованный список транзакций»). Закрепиться на v7 ради Bridge значило бы начинать новый проект на предыдущей мажорной версии.

Мажорные версии `@module-federation/enhanced` и `@rspack/core` совпадают во всех приложениях. Независимо выкатывается код приложения, а не его тулчейн: совместимость рантаймов Module Federation разных мажорных версий между хостом и remote-приложением первоисточники не гарантируют.

## Consequences

- Для маршрутизации остаются два паттерна: хост владеет маршрутами (`route.lazy`, `patchRoutesOnNavigation`) или remote-приложение отдаёт вложенные `<Routes>`. Паттерн «у каждого приложения свой роутер» закрыт.
- `react-router` — `shared`-синглтон: у всех приложений один экземпляр роутера и его контекста, и мажорное обновление React Router проходит во всех приложениях сразу. React Router v8 требует `react` и `react-dom` 19.2.7+.
- Remote-приложение не запускается отдельно «из коробки», как при Bridge: для разработки ему нужна своя dev-обёртка с роутером.
- Если ради `createLazyComponent` или fallback'ов подключить `@module-federation/bridge-react`, Rspack-плагин сам включит подмену `react-router` и сломает синглтон. Вместе с пакетом обязательно `bridge.enableBridgeRouter: false`.
- Смена мажорной версии Module Federation или Rspack — одно согласованное изменение во всех приложениях, выкатываемое до того, как приложения с разными мажорными версиями встретятся на одной странице. Минорные версии могут расходиться.

## Considered Options

- React Router v7 и Bridge Router: сохраняет все три паттерна, но держит проект на прошлой мажорной версии и не решает ссылки между микрофронтендами.
- React Router v8 вместе с Bridge после проверки прототипом: связка официально не заявлена, и держаться она будет на поведении алиас-плагина, а не на контракте.
- Тулчейн каждого приложения обновляется независимо, совместимость рантаймов — часть контракта: проверять её пришлось бы тестами между версиями, о которых сами авторы Module Federation ничего не обещают.
