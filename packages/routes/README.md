# @yozhikom/finflow-routes

Префиксы remote-приложений FinFlow и их публичные адреса (ADR-0008). Ссылку на соседнее приложение или на собственный публичный адрес строят только через этот пакет. Если адрес поменяется, сломается сборка, а не ссылка у пользователя.

## Пример

```ts
import { prefixes, routes } from '@yozhikom/finflow-routes';

routes.transactions.build({ month: '2026-03', currency: 'RUB' });
// '/transactions?month=2026-03&currency=RUB'

routes.transactions.parse('/transactions?month=2026-13&category=c1');
// { category: 'c1' }: месяц неверного вида молча отброшен

routes.account.parse('/analytics'); // null: это другой адрес
```

## Адреса

| Адрес               | Построить и разобрать   | Параметры                                                             |
| ------------------- | ----------------------- | --------------------------------------------------------------------- |
| `/transactions`     | `routes.transactions`   | необязательные `category`, `month` (`YYYY-MM`), `currency`, `account` |
| `/transactions/new` | `routes.newTransaction` | необязательный `account`                                              |
| `/accounts/<id>`    | `routes.account`        | `id`                                                                  |
| `/analytics`        | `routes.analytics`      | нет                                                                   |

`build` собирает адрес из параметров. `parse` принимает путь с параметрами запроса или полный URL. Он возвращает типизированные параметры, а для чужого адреса возвращает `null`. Параметры неверного вида, например `month=2026-13` или неизвестную валюту, `parse` молча отбрасывает.

Есть ли сущность с таким `id`, пакет не проверяет. Это делает приложение, которому она принадлежит.

## Совместимость версий

Каждое приложение включает в свою сборку свою версию пакета. Поэтому разные версии должны понимать адреса друг друга.

В `fixtures/addresses.json` лежат «золотые» адреса: их строила текущая версия или одна из прошлых. Тесты проверяют, что каждый из них разбирается и что на каждый публичный адрес есть хотя бы одна фикстура.

Удалять или менять фикстуру можно только в мажорной версии. CI берёт фикстуры последнего тега `routes-v*` и смотрит, какие из них удаляет или меняет сам PR. Если такие есть, а в заголовке PR нет `!`, проверка падает. Ломающее изменение, которое уже влито в `develop`, следующим PR в вину не ставится.

## Какая версия нужна

- Новый адрес, параметр или валюта — `feat`, минорная версия.
- Переименование или удаление адреса, параметра или префикса — `feat!`, мажорная версия. Такое изменение выкатывают по шагам ADR-0011.
